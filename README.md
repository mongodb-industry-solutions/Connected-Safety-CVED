# Connected Safety CVED demo

When an airbag fires, the vehicle sends a standardized emergency message (COVESA CVED) to the cloud, where it is stored in
MongoDB and shown to a simulated emergency center (RTIC 911) within seconds.

```
 vissr-vehicle ──WebSocket── crash-agent ──HTTP──▶ vissr-cloud ──▶ MongoDB (crashes)
 VSS 6.1 + Occupant          Crash Monitor Agent    CVED tree   └─▶ rtic911 ──▶ MongoDB (rtic_alerts)
 trip feeder                 VSS → CVED, 2 messages             REST sink   API + dashboard
```

| Container | What it runs |
|---|---|
| `vissr-vehicle` | VISSR server with the VSS 6.1 and Occupant trees, and a feeder that plays a trip ending in a crash |
| `crash-agent` | Crash Monitor Agent (Ford): watches the airbag, maps VSS to CVED, sends a critical and a context message, then exits |
| `vissr-cloud` | VISSR server with only the CVED tree; its feeder stores each crash in MongoDB (`--mongosink`) and POSTs it to RTIC 911 (`--restsink`) |
| `rtic911` | RTIC 911 simulator: alert API and dashboard on http://localhost:5050 |
| `mongodb` | MongoDB Community, only in local mode |

Both VISSR servers use Memcache as state storage, inside their containers.

## Run it

Requirements: Docker and make.

```
cp .env.example .env
make start                    # local MongoDB; or: make start DB=atlas (set MONGODB_URI in .env)
```

Open http://localhost:5050: the first trip ends in a crash, and its alert arrives within a few seconds.

```
make crash                    # all scenarios, one after the other (about 2 minutes)
make crash SCENARIO=rollover  # one scenario: ammDemoTrip, copenhagen, dearborn, helsingor, rollover
make reset                    # delete the alerts and crash documents
make status                   # the Crash Monitor Agent shows "Exited (0)": it reports one crash and exits
make logs
make stop                     # make clean also removes the images and the local database
```

Every crash gets a new incident ID, so each one is a new alert. The scenarios are fictitious people and vehicles,
generated by `infra/vissr/vehicle/trips/makeScenarios.py`.

### MongoDB

- **Local (default):** MongoDB Community in the `mongodb` container, also reachable on `mongodb://localhost:27017`
  (e.g. `mongosh connected_safety_cved` or Compass).
- **Atlas:** `make start DB=atlas` uses `MONGODB_URI` from `.env`. On a shared cluster, set your own `DATABASE_NAME`,
  so that `make reset` only deletes your data.

Collections: `crashes` (one document per crash, the CVED tree as nested, typed fields) and `rtic_alerts`.

## How VISSR is included

VISSR is not copied into this repo. `infra/vissr/Dockerfile` clones [COVESA/vissr](https://github.com/COVESA/vissr) at a
pinned commit (`VISSR_REF`) and adds on top:

- `infra/vissr/patches/`: our VISSR changes that are not upstream yet, see its README.
- `infra/vissr/fordCollab/`: the Ford / COVESA demo files that are not upstream yet, see its README.

When one of them is part of VISSR, delete it here and bump `VISSR_REF` in `docker-compose.yml`. One image is built and
used by `vissr-vehicle`, `crash-agent` and `vissr-cloud` with different start scripts and configuration.

```
infra/vissr/
├── Dockerfile
├── patches/           VISSR changes not upstream yet
├── fordCollab/        CMA, VSS 6.1 / Occupant / CVED trees, vehicle HIM, Ford trip
├── vehicle/trips/     crash scenarios
├── cloud/             cloud HIM (CVED only) and feeder config
└── start-vehicle.sh, start-cma.sh, start-cloud.sh
rtic911/               RTIC 911 simulator (Next.js)
```
